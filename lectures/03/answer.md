# 第3回 解答

## 演習

- 第1回（素のLLM）とエージェントの回答の違い
  第1回の `app.ask` では「基礎・応用・発展」と一般的な分類を挙げ、講座の完了条件を特定できなかった。今回の `app.agent` は「基礎・実装・発展のうち、どれか1つに取り組めばその回の宿題は完了」と回答した。用語集の `homework-levels` と一致しており、関係する回として第1回も示した。
- `--trace` で見えたツール呼び出し
  「LoRAとQLoRAの違いは？」に対して、変更前は `search_glossary({'query': 'LoRA'})` と `search_glossary({'query': 'QLoRA'})` が呼ばれた。両方の定義がツールから返り、回答ではQLoRAがベースモデルの重みを量子化してメモリを節約する点を説明した。
- 1つの質問での LLM 呼び出し回数
  変更前のLoRAとQLoRAの質問では `requests=2`、`tool_calls=2` だった。
- 追加したツールと、docstring に書いた説明
  `make_quiz(lecture: int)` を追加し、指定回の用語を用語集から1つ選んで、問題と定義を返すようにした。該当する用語がない場合は、その旨を返す。docstring には「指定した回の確認問題を1問作る。確認問題を求められたときに使う。」と書いた。
- 動作確認
  `--list-tools` で登録を確認した。「第2回の内容から確認問題を1問出して」では `make_quiz({'lecture': 2})` が呼ばれ、「事前学習」の意味を問う問題が表示された。ツールは答えも返したが、利用者向けの応答では答えを明かさなかった。この実行は `requests=2`、`tool_calls=1` だった。 `uv run pytest -q` は15件すべて成功した。

## 宿題

- 取り組んだレベル
  基礎
- やったこと
  `make_quiz` の追加前に、`app/tools.py` の `search_glossary` の docstring だけを変更した。検索語を「1つだけ入れる（例：LoRA）」という説明から「まとめて入れる（例：LoRA QLoRA）」に変えた。同じモデル（`gemini-3.5-flash-lite`）に「LoRAとQLoRAの違いは？」と変更前後に1回ずつ質問し、`--trace` の出力を比較した。
- 結果

  | 観察項目 | 変更前 | 変更後 |
  |---|---|---|
  | 検索の引数 | `LoRA` と `QLoRA` を別々に指定 | `LoRA QLoRA` を1つの引数で指定 |
  | ツール呼び出し回数 | 2 | 1 |
  | LLMへのリクエスト回数 | 2 | 2 |
  | 入力トークン数 | 1,196 | 891 |
  | 出力トークン数 | 199 | 203 |

  変更後も回答は両方の用語を説明し、関係する回として第2回を示した。変更後のトレースではツールの戻り値が途中で省略され、表示から確認できたのはLoRAの項目までだった。
- 気づき・疑問
  ツールの説明文を1か所変えただけで、今回の実行では検索の回数と引数が変わった。検索が1回減っても、モデルへのリクエスト回数は同じだった。今回は各条件1回の比較なので、別の用語の組み合わせでも検索をまとめられるか、必要な定義を拾えるかを追加で確かめたい。
